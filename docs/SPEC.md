# v0.2 acceptance

Deliver a portable, low-interruption coding workflow as an independent open-source repository. Retain the short path for small tasks. Reuse approved scope and authorization; ask only for missing business facts, preferences, credentials or permissions.

1. Applicable specialist components are read or natively invoked before executing their stage. Record actual paths, hashes, invocation mode, adaptation and output. Degrade only with a concrete availability/restriction reason. File presence is distinct from invocation and successful output.
2. Adapt TDD seam confirmation, grilling decisions, spec/ticket confirmations and tracker side effects explicitly. Technical facts are investigated; existing approved decisions are reused. Current environment instructions take precedence.
3. Review covers the complete deliverable tree, including staged, unstaged, deleted and nonignored untracked files. Snapshot commands preserve the real index and HEAD. Standards and Spec review independently; required independent review remains unmet if unavailable.
4. Check commands save full combined output, original command status and tree identity. Discovery counts and pass counts remain distinct. Changed trees invalidate affected checks. Necessary unverified conditions prevent VERIFIED.
5. Component receipts, command results and archived evidence are hash verifiable. A record validator checks declared conditions, component evidence, review axes and code-tree correspondence. These tools validate supplied records; they cannot prove an agent read or reasoned correctly.
6. Performance tasks fix driver, environment, concurrency, warmup, data and statistics; retain raw samples and verify metric meaning. Tests derive expectations independently from the behavior contract.
7. Installation protects unmanaged files, local edits, symlinks and same-version drift. Stage a full package, preserve the previous directory and recover after interruption without accepting a mixed version. Project template links survive instantiation.
8. Document setup, compatibility limits, optional dependencies, license, tests and CI. Publish only generic assets and synthetic fixtures. Keep one canonical product source; archive the old knowledge-base package and update local installations.

Tests: synthetic Git tree coverage/index preservation; failing check with long output; stale/missing evidence rejection; missing independent review; interrupted upgrades with preserved edits; installed helper execution. A fresh-context forward task and independent two-axis review supplement deterministic tests. Native client discovery and full cross-client coding are separate claims.
