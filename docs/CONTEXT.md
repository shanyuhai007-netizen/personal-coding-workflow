# 会话上下文决策

适用于执行本工作流的编码会话。目标：主上下文尽量保持在模型敏锐区间内。控体积靠委派、指针与落盘；压缩只是宿主兜底，不作为主动策略。

## 阶段边界

去留决策只在阶段边界做，即 [WORKFLOW §7](../WORKFLOW.md) 的研究、设计、实施、验收自然边界。阶段内默认继续；剩余工作已可独立执行（不需接续当前推理线）时，可拆子上下文执行（代码库探查见 [ADAPTERS 探查委派](../ADAPTERS.md#组件步骤适配)，并行见 WORKFLOW §4）；需要接续当前推理线的部分不委派——子上下文收到的是任务说明，不是会话推理线。

## 四项主动策略（按序排除）

1. **继续**：零成本零损失，最先排除。下一阶段需要本阶段一手推理（如 spec 建立在事实核查与拆票思考上），或窗口仍充裕时选择。
2. **新会话（清空）**：仅当本会话内容对下一步全部可弃，或已完整落盘。落盘完整＝未落盘决策为零。
3. **handoff 文件**：仅跨工具、跨目录、交给他人或中途分叉侧任务；买的是可携带性，不携带就不需要。
4. **subagent 委派**：任务可无人值守独立完成时（探查、两轴评审、research、可独立执行的实施切片）；主会话只收结论与指针。

## 压缩：宿主兜底，非策略入口

宿主在长会话可能自动摘要上下文（ZCode 2026-11-20 会话观察；其余宿主未实测，以会话实际行为为准）；落盘未完成前不得主动触发压缩。断点出口按条件选择：未落盘决策为零 → 新会话；落盘不完整或无法判断 → 压缩后继续——压缩至少保留有损摘要，直接清空可能丢推理。

任何非「继续」的移动都把一手推理降为二手摘要；只在留下比失去更贵时才付这笔钱。

## 落盘纪律与回传约束

断会话、压缩或清空前，未写进任务记录的决策、阻塞与下一动作先落盘（WORKFLOW §7 状态字段），证据按 §5.6 记指针。子上下文回传限结论与指针并限字数（对照上游 code-review 每轴 400 词纪律），不整段回传原始输出——原始产物落盘，主会话持指针。

## 委派的成本

委派不省总 token：每个子上下文重读文件与规则，回传再进主窗口（iteration-2 实测 subagent_tokens 单点总量 6.5M 差值，见 CHANGELOG 阶段级成本记录）。委派换来的是主窗口体积与独立性；成本口径按 [EXECUTION](EXECUTION.md) 阶段成本声明，`basis` 注明计量来源。
