# 性能任务的测量契约

先固定以下字段，再记录前后结果；做不到同口径时说明限制，保留已观察改善与因果归因的区别。

| 项目 | 必须记录 |
|---|---|
| 版本 | 代码树、配置、driver hash / 运行命令 |
| 环境 | 运行位置、网络路径、服务实例、资源与数据规模 |
| 负载 | driver 串行 / 并行、并发数、调度方式、间隔、超时和重试 |
| 隔离 | 其他浏览器 / 轮询 / 作业是否停用；有重叠时用 request ID 关联 |
| 前置 | 冷启动 / warmup / first 定义，暖冷样本分别标识 |
| 指标 | 名称、单位、起止边界、原始字段、缺失 / 失败处理 |
| 分桶 | 服务端 hit / miss / generation 还是代理估计；首拍与各桶 n |
| 统计 | 分位数算法、样本数、原始样本及复算脚本 |
| 验收 | 阈值、失败条件、支持的结论与未证明的范围 |

请求延迟、缓存年龄、后台刷新耗时是不同指标。采用前先让独立上下文按原始字段核对语义；从数字到 spec / ADR / 票的推论需可追溯。小样本高分位接近最大值，应报 n 及限制。代理分桶不能写成精确缓存命中率。

前后改变 driver 或环境时，优先补同协议复测；已有数据仅作对应窗口描述。保留原始样本、脱敏 driver、环境说明、算法和 hash 到持久证据目录，并验证副本可独立复算。凭据及私有样本按项目数据范围留本地。
